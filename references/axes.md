# 能力轴定义与判据细则

## 为什么是"能力轴"而不是别的

三种候选轴设计的判别结果：

| 候选 | 是否可用 | 理由 |
|------|---------|------|
| 知识点（KP1..KP20） | ❌ | 轴数随主题变（8~20 根不等）→ 跨主题无法比较。且"记住 KP3 的定义"不是一项能力，是记忆的一个片段。 |
| Bloom 六级（L1-L6） | ❌ | **纵向层级不是横向能力。** 任何人在 L1 强 L6 弱是必然结果 → 雷达图退化成一个"你已经知道多少"的量表，形状没有区分度。这是最容易犯的错，因为 Bloom 已经在 材料驱动型 Skill 里用顺了。 |
| 能力维度 | ✅ | 从学习目的反推得来，跨主题语义稳定（"结构化拆解"在 AI 产品和围棋里都成立），每轴有客观判据可判真假。 |

## 轴的三条硬要求

1. **跨主题稳定**——同一根轴在任意主题下都能评分。
2. **判据可判真假**——能说清"什么表现算达标"，不能是"理解深入"这种循环定义。
3. **互相不重叠**——两根轴不能同时被同一批 KP 主导，否则雷达图会出现两根一样长的轴，信息量归零。

## 初始轴池（6 根）

| ID | 名称 | 判据（怎样算达标） | 典型失误信号 |
|----|------|------------------|------------|
| A1 | 概念辨析 | 能说清两个近似概念的本质区别，并给出区分判据，而非背定义 | 遇到"这两个有什么区别"只能复述两者各自定义 |
| A2 | 结构化表达 | 能把复杂对象拆成有层级、可判定的结构，拆完能指着说"这几块之间的关系是……" | 只能线性罗列，不能表达从属/并列/因果 |
| A3 | 边界与风险意识 | 能主动说出"这招在什么情况下不成立""什么时候会翻车" | 只讲什么时候能用，不讲什么时候不能用 |
| A4 | 工程直觉 | 能判断一个方案落地时会卡在哪（数据、依赖、成本、人的配合） | 只谈理想流程，不谈卡点 |
| A5 | 判断取舍 | 面对多个选项能给依据、明确选一个并承担结论 | 罗列所有选项利弊，不下判断 |
| A6 | 度量设计 | 能设计出可判真假的验证方式（不是"感觉好多了"） | 用"用户体验更好"当验收标准 |

## 扩轴规则

新轴不是"看着需要就加"。三个条件同时成立才允许加：

1. 现有 6 根轴里有 ≥2 根都无法承载这批 KP（不是"有点勉强"，是明显不贴）
2. 这根轴能跨至少 2 个主题成立（过不了这条就只能是主题私有轴，私有轴不能进全局池，只能放主题内）
3. 判据能写成一句可判真假的话

加了之后，全局池上限建议 **8 根**。超过 8 根雷达图读起来费劲，且说明轴粒度太细——通常该合并而不是加。

## 主题私有轴

某些主题确实有全局轴装不下的能力（如"围棋的定式记忆"）。处理：

- 私有轴写进主题的 `立项.json`，标 `"global": false`
- 私有轴**不参与**跨主题雷达图叠加，只在主题内评分
- 报告里分开画：全局轴雷达图（可跨主题比）+ 主题私有轴列表（表格）

## 轴的评分数据从哪来

不手填。轴分由该轴下所有 KP 的测试记录算出：

```
cov(A)   = 已测 KP 数 / 该轴 KP 总数
depth(A) = Σ bloom_now / (5 × 该轴 KP 总数)
score(A) = 100 × (0.3 × cov + 0.7 × depth)
```

权重 0.3/0.7 的理由：
- 只算 depth → 学了 3 个到 L5、剩 20 个没学，分虚高（会误判为优势）
- 只算 cov → 学 1 个到 L6，分也虚高（覆盖率 100% 但深度极浅）
- 深度权重更高，因为"学过"不等于"会用"，而学习引擎的目标是后者

## 覆盖率的特殊约定

未测的 KP 记 `bloom_now = 0`，但**不等于"考了 0 分"**：
- 它在 `cov` 里体现为未覆盖（拉低 cov）
- 它在 `depth` 里贡献 0
- 报告里显示为"覆盖 3/8"，让人看见还有多少根本没碰过

不要把未测和"测了但不会"混为一谈。前者是还没学，后者是学了没学会——处置方式完全不同（一个排进队列，一个进弱点池）。
