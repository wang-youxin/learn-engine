# 雷达图：算分、优劣判定、影响推演

## 一、算分

见 `axes.md` 的算分公式。此处只强调一件事：**所有数字必须来自测试记录，不能来自印象。**

脚本：`scripts/radar.py`
```bash
python radar.py --profile <profile.json> --topic <主题目录> --out <输出.html>
python radar.py --demo        # 看效果用
```
脚本输出：当前分、目标分、缺口、覆盖率、深度、枢纽度、初步判定。

## 二、目标线为什么必须有

没有目标线的雷达图只能回答"我哪里强哪里弱"，回答不了"我离能做成还差多少"。而用户要的是后者——"优势会带来什么影响""调整应该怎么调整"，都以"离目标多远"为前提。

```
target(A) = 100 × (0.3 × 1.0 + 0.7 × 平均(target_bloom)/5)
```
假设该轴所有 KP 都达标时的分数。

## 三、优劣判定：分两层

### 第一层（脚本出，基于两个可机械计算的因子）

| 判定 | 条件 | 含义 |
|------|------|------|
| 真优势 | gap ≤ 15 且 hub ≥ 2 | 接近目标 + 是枢纽。学它能解锁后面一片。 |
| 达标·单点支撑 | gap ≤ 15 且 hub = 1 | 到了目标，但只被一个 KP 依赖。局部有用。 |
| 达标但非枢纽 | gap ≤ 15 且 hub = 0 | 到了目标，但不解锁任何东西。**看着是优势，其实不是杠杆。** |
| 接近目标 | 15 < gap < 30 | 差一截，补一下就到。 |
| 关键短板 | gap ≥ 30 且 hub ≥ 1 | 缺口大且卡着别人的路 → 最高优先级。 |
| 独立短板（待判定） | gap ≥ 30 且 hub = 0 | 缺口大但不卡别人。**重要不重要，脚本判不了。** |
| 认知断层 | gap ≥ 40 且上游全达标 | 不是没学，是学歪了 → 要重讲不是重练。 |

### 第二层（AI 裁决，只针对"独立短板（待判定）"）

必须查 S0 的「动作 → 能力轴 映射表」：

- 该轴被某个目标动作 G 依赖 → **是真短板**，写进补充清单
- 该轴不被任何 G 依赖 → **可以放一放**，报告里明说"不影响你的目标动作，不建议现在花时间"

> ⚠️ 不能因为"hub=0"就判"可忽略"。度量设计这类轴不卡别人，但它是"评估集设计"的前提——它重要与否取决于你的目标，不是取决于依赖图。

## 四、枢纽度（hub）怎么算

hub(A) = 依赖图中，有多少个**别的 KP** 依赖本轴的任一 KP。

不是数本轴内部 KP 的依赖，是数**外部**依赖。A2 结构化表达内部 KP4→KP5→KP6 那是轴内链条，不构成枢纽。

意义：hub 决定"先补哪个最划算"。hub=5 的轴一补就解锁 5 个 KP；hub=0 的轴补完还得挨个补别的。

## 五、影响推演：必须能追到源头

用户要"这个劣势会带来什么影响"。这条最容易变成漂亮话。硬规则：

**每条影响必须追到 S0 映射表里的某个 G 动作。** 追不到就删掉，不许软编。

推导链（缺一环即不可写）：

```
KP 事实（测试记录） → 轴分（脚本算出） → 依赖某 G 动作（S0 映射表） → 具体后果
```

### 报告条目模板

```
【关键短板】A6 度量设计 · 当前 51 / 目标 100 · gap 49 · hub 0

为什么是短板：
  KP10「评估三集」bloom_now=1（目标 L5），KP11「双线迭代」bloom_now=2（目标 L5）——两个 KP 都没学进去。
  上游 KP7「技术边界四类」bloom_now=2 目标 L4 → 也不达标，所以这不是孤立问题。

为什么不是别的原因：
  不是"没学"——两题都作答了，是学了没到目标级（能复述定义但不会设计）。
  不是"前置没学"——KP5「评估体系」bloom_now=4 已达标，前置是通的。

带来什么影响：
  G3「设计评估集」依赖 A6 → 你写出来的评估集只会覆盖准确率，
  会漏掉"指标达标但体验变差"这类问题。（依据：S0 映射表 G3 → A6）

怎么调整：
  ① 先补 KP10（估 3 天，目标 L4）——用你自己产品的历史数据做一遍基线/回归/边界三集
  ② 补 KP11 前置：KP10 达标后再动
  ③ 这两项达标前，G3 不算学会，S6 报告里 G3 一栏标"未达成"
```

### 反例（不许出现）

```
❌ 【短板】A6 度量设计
   影响：会让你在 AI 产品设计上缺乏系统性，容易被竞品甩开，职业发展受限。
   —— 没有追到任何 G 动作，纯软编。
```

## 六、报告里必须有的四段

用户明确要求"为什么这个是优势，为什么那个是劣势，优劣势会带来什么影响，调整应该怎么调整"：

1. **优势清单**（真优势 + 达标但非枢纽分开列，别混）
2. **短板清单**（关键短板 + 独立短板分列，独立的标"待判定"或"已裁决"）
3. **影响推演**（每条带证据链）
4. **下一步动作**（具体到：补哪个 KP、几天、目标级、什么算完成）

第 4 段不许只写"加强 X 轴"。要写"补 KP10，3 天，目标 L4，用真实数据做三集"。

## 七、雷达图不做什么

- 不做人格测评。分数是能力达成度，不是性格。
- 不做跨人比较。"我在概念辨析上 86 分"只跟自己的目标线比，不跟别人比。
- 不追求好看。形状不规则是正常的，形状好看说明轴选得不细或数据太假。
- 不隐藏缺口。缺口就是缺口，不用"总体良好"这类模糊话盖过去。
