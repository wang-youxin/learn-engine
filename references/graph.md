# 知识图谱规范：边、杠杆、分段测试

本文件管三件事：**知识点怎么连边**、**顺序怎么排**、**测试怎么分段**。

---

## 一、知识点单位（不按课时，按可独立验收的最小单元）

### KP 的定义

> **一个 KP = 一个能独立出题、能独立验收的最小知识单元。**

### 判断法

**能不能就它单独出一道"换个场景能不能用"的题？**
- 能 → 是一个 KP
- 不能 → 还太大，拆

反例：「AI 产品设计」——太大，一个题考不完。
正例：「用 AI 介入深度给一款产品归类并说出判定依据」——能考、能判、能验收。

### 数量控制

- 一个主题 **12-20 个 KP**。少于 12 → 主题太窄，考虑合并或加深。
- 多于 20 → 主题太大，**切子主题**（拆成两个主题，各自一套轴子集）。

### KP 与课时的关系

**引擎不认课时。** 课时是"材料如何组织"的属性，KP 是"知识如何切分"的属性。

- 一个 KP 可以跨 3 节课（如同一个概念在 第一节讲、后面再深化）
- 一节课可以贡献 0 个 KP（纯背景介绍）
- 一个 KP 可以来自 0 节课（AI 自己检索的材料）

所以图谱和课程是**多对多**关系。S5 学 KP 时，AI 去料库里找这个 KP 的全部材料来源讲，不受课时边界限制。

## 二、三种边

```
KP7 ──deps──→ KP4            硬前置：不懂 KP4 学不了 KP7
KP7 ──related──→ KP12        横向关联：常被混淆 / 特例 / 同源
KP7 ──contrast──→ KP15       对立：同一维度的两个极端
```

### 2.1 deps（硬前置）

**含义**：不懂 A 就学不了 B。

**判定标准**（不是"相关"就算）：问自己——**如果用户完全不懂 A，学 B 会不会卡住？**
- 会卡住 → deps
- 只是"背景知识" → related

**例**：
- deps：KP4「评估三集」→ KP7「数据闭环」（不懂怎么评估就不知道数据往哪回流）
- related：KP4「评估三集」→ KP6「灰度上线」（都属评估体系，但互不阻塞）

**排程作用**：硬约束。B 的开始时间 ≥ A 达标。

### 2.2 related（横向关联）

**含义**：A 与 B 有知识结构上的亲缘关系。

三种常见类型：
1. **易混型**——学习者大概率会混（如「自注意力」vs「RAG 检索」）
2. **特例型**——A 是 B 的特例或推广（如「贪心算法」是「启发式搜索」特例）
3. **同源型**——A 和 B 出自同一底层原理的不同应用

**教学作用**：讲 A 的时候主动带出 B。对易混型尤其重要——**易混型是学习者弱点的高发区**（把两个近义概念当成一个、把机制和结果搞混）。这些必须连 related 边，并在讲 A 时主动做区分。

### 2.3 contrast（对立）

**含义**：A 和 B 是同一维度的两个极端。

**测试作用**：同组出题最能测辨析能力（A1 概念辨析轴直接受益）。

**例**：
- contrast：「加 AI」vs「AI 原生」
- contrast：「规则引擎」vs「大模型」
- contrast：「基线集」vs「边界集」

### 2.4 硬规则：每 KP 至少 1 条边

**孤立 KP = 图谱没建好**，S2 闸门直接打回。

理由：一个没有任何前置、也不关联任何其他知识点的知识点，要么是超纲（不属于这个主题），要么是没想清楚它跟整体的关系。

## 三、图谱数据结构

```json
{
  "topic": "ai-pm",
  "axes": ["A1", "A2", "A3", "A4", "A5", "A6"],
  "kps": [
    {
      "id": "KP7",
      "name": "效果评估体系（基线/回归/边界）+ 数据闭环",
      "axis": "A6",
      "target_bloom": 5,
      "deps": ["KP1", "KP2"],
      "related": ["KP15"],
      "contrast": [],
      "value": 0.9,
      "freq": 0.7,
      "source": ["https://..."],
      "conflict": false,
      "status": "untested",
      "bloom_now": 0
    }
  ]
}
```

| 字段 | 含义 | 填法 |
|------|------|------|
| `deps` | 硬前置 KP ID 列表 | 见 2.1 |
| `related` | 横向关联 KP ID 列表 | 见 2.2 |
| `contrast` | 对立 KP ID 列表 | 见 2.3 |
| `value` | 对目标动作的权重 0-1 | 从 S0 映射表算：被几个 G 动作依赖 × 依赖强度 |
| `freq` | 行业使用频率 0-1 | 检索时的实践频率 + 岗位 JD 出现频次 |
| `target_bloom` | 目标 Bloom 级 | S0 定的目标动作要求它到哪级 |
| `bloom_now` | 当前水平 | S3/S5 测试写入，0=未测 |

## 四、杠杆排序（顺序怎么排）

### 4.1 三条硬约束 + 一条软排序

```
Step 1 拓扑约束（硬）：deps 未达标的 KP，其后继不得排前面
Step 2 掌握度放行（硬）：bloom_now ≥ target_bloom - 1 才允许进下一个 KP
Step 3 Pareto 前置（软）：核心 20% 尽量提前（在拓扑允许范围内）
Step 4 杠杆降序（软）：leverage 高的优先
```

### 4.2 leverage 公式

```
leverage(KP) = 0.5 × hub_norm + 0.3 × value_norm + 0.2 × freq_norm
```

| 因子 | 原始值 | 归一化 |
|------|-------|--------|
| `hub` | deps 入度（它卡住几个下游 KP） | 除以全图最大入度 |
| `value` | 对目标动作的权重 | 已经是 0-1 |
| `freq` | 使用频率 | 已经是 0-1 |

**权重理由**：
- hub 占一半——因为 hub 决定"学会它能解锁多少"，这是教学法里瓶颈节点实验的直接结论（乘法卡 2 个下游，减法卡 0 个）
- value 占三成——目标导向的直接体现
- freq 占两成——但不能更高，否则会变成"只学最常用的"，深度不达标

### 4.3 Pareto 核心 20% 怎么定

**两个信号取并集**：

| 信号 | 取法 |
|------|------|
| 最重要 20% | 按 `value` 降序取前 ⌈N×0.2⌉ 个 |
| 最常用 20% | 按 `freq` 降序取前 ⌈N×0.2⌉ 个 |

并集 = 核心队列，**在拓扑允许范围内永远排最前**。

### 4.4 冲突处理（重要）

**核心 KP 依赖的某个 KP 还没达标时，不许跳过去硬学核心。**

正确做法：把"最短路径打通前置"插到最前面——即从核心 KP 出发反向找最短前置链，先补链上的。

硬学核心的后果是"学过但没学会"，比晚学更糟：既消耗了初期的高兴趣，又留下一个假掌握的坑。

### 4.5 每日队列

```
可学集合 = { KP | 所有 deps 已达标 } 
          ∩ { KP | bloom_now < target_bloom }
队列 = 可学集合中 leverage 最高的 3-5 个
每 KP 估 2-4 小时（按 target_bloom × KP 复杂度估）
```

切片原则：**宁可一天 3 个学透，不要 5 个学半生。**

## 五、分段诊断：5 阶段 × 4 题

### 5.1 为什么分段

一次考 20 题的三个问题：
1. 用户中途疲劳 → 后面的题质量掉 → 数据被污染
2. 结果来得太晚 → 当天学不了
3. 全部答完才知道缺什么 → 中间无法调整策略

分段解决全部三个：每 4 题答完立刻判级、立刻给下一步、当天就能开始学。

### 5.2 五段设计

| 段 | 题数 | 探针类型 | 测什么 | 答完的产出 |
|----|-----|---------|--------|-----------|
| **T1** | 4 | 广度探针 | 每轴 1 题，测 L2 理解 | 哪些轴完全没底 |
| **T2** | 4 | 深度探针 | T1 最弱的 2 根轴各 2 题，测 L3 应用 | 这两轴卡在哪一层 |
| **T3** | 4 | 迁移探针 | 跨轴组合题，测 L3-L4 | 是不是"碎片式会" |
| **T4** | 4 | 归因探针 | 对仍不达标的 KP 追问，测 L4-L5 | 没学过 vs 学歪了 |
| **T5** | 4 | 验收探针 | 对着 S0 目标动作出题，测 L5-L6 | 离"能做到"还差什么 |

**关键**：T2-T5 的题目由前面段的结果决定（自适应出题）。20 题不是固定题库。

### 5.3 每段答完的固定输出

不许等全部答完才给结论。

```
第 N 段结果（4 题）
├─ 本段判级：逐题对/错 + 达成 Bloom 级 + 即时反馈
├─ 当前能力快照：各轴当前分（雷达实时更新）
├─ 缺学清单（累积）
├─ 建议下一步：今天该学哪 2-3 个 KP
└─ 连续不达标 ≥3 个 KP → 提示走 S7 定制补充，别死磕
```

### 5.4 缺学清单：归因三分法

这是分段测试的核心产出。一次考完只知道"错了"；分段能区分三种错因，三种对应三条不同处置路径。

| 归因 | 判定 | 处置 |
|------|------|------|
| **没学过** | bloom_now = 0（未测/未接触） | 排队进 S5 正常学 |
| **被前置卡住** | bloom_now 低，但 deps 里至少一个未达标 | **先解前置**，本 KP 排队等待 |
| **学歪了** | bloom_now > 0 但明显低于目标，且 deps 全达标 | → **S7 定制补充**（重新讲，不是重练） |

```
| KP | 名称 | 当前 Bloom | 目标 Bloom | 缺口 | 归因 | 处置 |
|----|------|-----------|-----------|------|------|------|
| KP7  | 效果评估体系   | 2 | 5 | 60%  | 上游已达标 → 这层没学进去 | S5 补学 |
| KP12 | 多轮迭代策略   | 0 | 4 | 100% | 前置 KP7 未达标 → 先解前置 | 排队等待 |
| KP15 | 成本估算模型   | 1 | 4 | 75%  | 已测且错 → 学歪了 | S7 定制补充 |
```

### 5.5 与 S5 后置题的区别

| | S3 分段诊断 | S5 后置题 |
|---|------------|----------|
| 时机 | 学之前 | 学完立刻（30 分钟内） |
| 目的 | 定起点 + 归因 | 判定是否过关 |
| 数量 | 20 题（5 段×4） | 每 KP 2-3 题 |
| Bloom | 按目标级 −1 到目标级 | 按目标级 |

同一 KP 两套题库，不可混用。**同一批题不许既当诊断又当验收**——用户背过答案，测不出真水平。

## 六、图谱的常见失败模式

| 失败 | 症状 | 修法 |
|------|------|------|
| KP 太粗 | 一个 KP 出一道题考不完 | 按"能不能单独出场景题"拆 |
| KP 太碎 | 一堆 KP 都在说同一件事 | 合并；检查是否 related 边漏标 |
| 全是孤岛 | 没有任何边 | 逐个问"它跟谁容易混""它是谁的前置" |
| deps 滥用 | 什么都互为前置 → 无法排序 | 严格用"不懂 A 会不会卡住 B"判定 |
| 没有 value | 所有 KP 的 value 都是 1 | value 必须从 S0 映射表算，不是拍脑袋 |
| 忘了冲突标记 | 两个来源矛盾被强行调和 | 回到 sources.md 的冲突处理规则 |
