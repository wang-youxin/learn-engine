# 来源分级与拆 KP 规范

## 一、检索策略

S2 至少做 3 组方向不同的检索。少一组就容易只看到一面。

| 方向 | 目的 | 关键词构造 |
|------|------|-----------|
| 同行做法 | 跟用户情况相近的人/产品怎么做 | 领域 + 阶段 + 规模，如"AI 产品经理 技能要求 2026" |
| 权威公开资料 | 官方文档、教材、论文、定义 | 领域 + "官方文档 / 论文 / 教材 / 标准" |
| 现成方案 | 有没有现成清单/课程/题库可直接参考 | 领域 + "清单 / 学习路径 / 知识图谱 / 题库" |

质量把关：优先近 2 年、有具体内容、可验证来源的。**搜不到就明说"该领域公开资料稀缺"，改用相邻领域基准并标注不确定——不许用记忆里的印象充数。**

## 二、来源分级

| 级 | 类型 | 处理 |
|---|------|------|
| **A** | 官方文档 / 权威教材章节 / 论文 / 有署名的实战复盘 | 优先采信，可单独支撑一个 KP |
| **B** | 高质量技术博客 / 行业深度分析 / 经典原始出处 | 可采信，需与另一来源交叉验证 |
| **C** | 营销号 / 无署名博客 / 内容农场 / AI 生成摘要 | ❌ 不进料库 |
| **D** | 超过 2 年的时效性技术教程 | ❌ 不用（经典文献除外：Bloom 原文、Attention Is All You Need 等） |

分级标准说明：
- "有署名"是关键——能追到人的技术博客可以是 B，无署名的转载一律 C。
- D 类排除针对"会过时"的技术内容。2024 年的 "如何用 LangChain" 之类现在多半是错的。经典理论文献不过期，属 A。

## 三、拆 KP 的规范

每个 KP 必须带齐 5 项，缺任何一项不进料库：

| 项 | 要求 |
|---|------|
| ① 归属能力轴 | 挂到 A1-A6 之一（主题私有轴标 global=false） |
| ② 目标 Bloom 级 | 这个 KP 为了支撑目标动作，需要达到哪一级 |
| ③ 来源链接 | ≥1 个，A/B 级 |
| ④ 前置依赖 | 依赖哪些 KP（可为空） |
| ⑤ 时效标注 | 时效性内容标"截至 YYYY-MM" |

### KP 的粒度标准

- **一个 KP = 一个能独立出题、能独立验收的最小单元。**
- 判断法：能不能就它单独出一道"换个场景能不能用"的题？能，就是一个 KP。不能，说明它还太大，拆。
- 上限：一个主题 KP 总数控制在 12-20 个。超过 20 个说明主题太大，该切子主题。

### 双标准筛选（沿用 材料驱动型 Skill）

每个 KP 要同时满足：
1. **推动目标能力**——补它能让某根轴的分数往目标线走
2. **当下还在用**——有当下的实践/工具/岗位要求佐证，不是纯理论

不满足 → 降级进"背景区"（可以写进补充材料，但不占 KP 编号，不参与排程与评分）。

## 四、冲突处理（不许调和）

两个来源对同一件事实质矛盾时：

```markdown
### KP7 · 效果评估体系
- **冲突标记**：conflict: true
- **说法 A**：基线集/回归集/边界集 三分法（来源：[官方文档链接]，A 级）
- **说法 B**：应加第四集"对抗集"（来源：[论文链接]，A 级，2025-08）
- **处理**：并列保留，不裁决。S3 出题时避开此点，或出题时明确说"有两种做法，说出各自适用场景"。
```

**绝对不许**：自己编一个"综合两种说法"的版本。那是幻觉，不是整合。

## 五、时效性检查

| 内容类型 | 时效风险 | 处理 |
|---------|---------|------|
| 工具用法、API、框架 | 高（半衰期约 1 年） | 必须标"截至 YYYY-MM"，且优先用官方文档 |
| 产品形态、岗位要求 | 中（约 2 年） | 标来源日期 + 岗位出处 |
| 基础理论、方法论 | 低 | 不强制标日期 |

## 六、料库条目的写法

```markdown
### KP7 · 效果评估体系（基线/回归/边界）+ 数据闭环
- **归属轴**：A6 度量设计
- **目标 Bloom 级**：L5（评价）
- **前置依赖**：KP1（评估在 AI 产品中的位置）、KP2（AI 与传统产品差异）
- **来源**：
  - [官方文档] 评估集三分类 —— https://example.com/docs/eval-sets （A 级，截至 2026-08）
  - [深度分析] 为什么指标达标体验变差 —— https://example.com/blog/metric-vs-experience （B 级，2026-05）
- **是什么**：评估三集——基线集（标注测试集定下限）、回归集（迭代不降能）、边界集（bad case 找盲区）；指标不只度量准确度，还要度量体验（如 AI 客服的转人工率）。
- **为什么推动目标能力**：让 G3「设计评估集」从"会背三集名称"到"能设计出漏测指标"（目标 L5）。
- **为什么当下还在用**：ragas / deepeval / promptfoo 已是 2026 AI 产品标配；企业落地翻车八成在"场景没假设清"或"POC 没算成本"。
- **用途延伸**：① 建三套评估集 ② 防"指标达标体验差" ③ 隐式反馈替代弹窗（修改数据=优化信号）④ 面试讲评估体系 ⑤ 接 A3 边界意识。
```

结构与 材料驱动型 Skill 的知识树一致（是什么 / 为什么推动 / 为什么还在用 / 用途延伸），只是把"归属轴 + 目标 Bloom 级 + 前置依赖 + 来源分级"补进去了。
