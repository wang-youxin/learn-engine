## 0. 它不是什么

| 不是                      | 为什么排除                                                                                                                                                             |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 不是"再做一个 「材料驱动型」学习 Skill" | **两个并列的 Skill，不是主从关系。** 材料驱动型 Skill 是**材料驱动**（先有逐字稿才开工，产 3 份文件）；本 Skill 是**目标驱动**（先定目标，AI 自己找料，产状态+路径+报告）。二者可共享零件（Bloom 判级、双标准筛选、补充材料范本、档案协议），但不存在"降级/上游"关系，各自独立触发、独立存储。 |

## 1. 设计公理（后续所有争议按这六条判）

1. **证据优先**——每个 KP 必须挂来源；每个分数必须能追到一次测试。挂不上来源的 KP 不许进料库，测不出的分数不许显示。
2. **状态驱动路径**——学习顺序不是编辑决定的，是学习者状态算出来的。状态变，顺序变。
3. **相对目标谈优劣**——优势/劣势是相对"你的目标"，不是相对"别人"。所以雷达图必须叠加目标线。
4. **影响力先于分数**——轴的优先级看它卡住谁，不看它自己分多低。

## 2.5 · 四个硬约束的设计落点（v2 新增）

| 用户需求                       | 落点 | 关键设计                                                                                         |
| -------------------------- | -- | -------------------------------------------------------------------------------------------- |
| **知识树按知识点不按课时**            | S2 | KP = 最小可独立出题、可独立验收的单元。一个主题 12-20 个 KP。课时只是容器，引擎不认。                                           |
| **知识点之间要连边**               | S2 | 图谱而非树。每 KP 有 `deps`（硬前置）+ `related`（横向关联）+ `contrast`（对立）。**每个 KP 至少 1 条边**，孤立 KP 说明它没被真正理解。 |
| **测试分 5 阶段共 20 题**         | S3 | 分段诊断：每段 4 题，答完一段立刻判级+定下一步，**不等 20 题全答完**。产出「缺学清单」。                                           |
| **兴趣衰减 → 最重要/最常用 20% 挪前面** | S4 | 杠杆前置调度。依赖图定先后，杠杆度定提前，掌握度定放行。                                                                 |

### 2.5.1 知识图谱的边（用户明确要求"知识点之间连边"）

三种边，作用不同：

| 边类型        | 含义                                     | 用途                                |
| ---------- | -------------------------------------- | --------------------------------- |
| `deps`     | 硬前置：不懂 A 就学不了 B                        | **排程硬约束**。B 的开始时间 ≥ A 达标          |
| `related`  | 横向关联：A 与 B 常被混淆 / A 是 B 的特例 / A 与 B 同源 | **教学编排**。讲解 A 时顺手带出 B，减少混淆        |
| `contrast` | 对立：A 和 B 是同一维度的两个极端                    | **测试编排**。同组出题，测辨析能力（直接喂 A1 概念辨析轴） |

每 KP 至少 1 条边（deps 或 related）。**孤立 KP = 图谱没建好**，闸门直接打回。

为什么要连边（不只是为了好看）：

1. **边 = 混淆来源**。学习者的弱点常常集中在"该连边却没连边"的地方——两个近义概念被当成一个，讲的时候不预警，混了也不知道。
2. **边 = 教学顺序**。related 边让 AI 讲 A 时能提前带出 B。
3. **边 = 杠杆计算**。deps 的入度就是枢纽度（见 §7）。

### 2.5.2 分段诊断：5 阶段 × 4 题（用户明确要求）

**为什么分段而不是一次 20 题**：一次 20 题有三个问题——
  
① 用户中途累了，后面的题质量掉，污染数据；
  
② 拿到结果太晚，当天学不了；
  
③ 全答完才知道缺什么，中间无法调整。

分段解决：每 4 题答完立刻判级，立刻给出「当前状态 + 下一段该学什么」，**当天就能开始学**。

| 阶段     | 题数 | 考什么                               | 答完立刻产出                       |
| ------ | -- | --------------------------------- | ---------------------------- |
| **T1** | 4  | 广度探针：覆盖全部能力轴，每轴 1 题，测 L2（理解）      | 哪些轴完全没底 → 立刻知道从哪下手           |
| **T2** | 4  | 深度探针：针对 T1 最弱的 2 根轴各 2 题，测 L3（应用） | 这两轴卡在哪一层 → 决定先补哪个 KP         |
| **T3** | 4  | 迁移探针：跨轴组合题，测 L3-L4                | 能不能跨轴组合调用 → 判断是不是"碎片式会"      |
| **T4** | 4  | 深度探针：对仍不达标的 KP 追问，测 L4-L5         | 是"没学过"还是"学歪了" → 分流到 S5 还是 S7 |
| **T5** | 4  | 验收探针：对着 S0 目标动作出题，测 L5-L6         | 离"能做到"还差什么 → 最终缺学清单          |

**每段答完的固定输出**（不许等全部答完）：

```
第 N 段结果（4 题）
├─ 本段判级：4 题逐题对/错 + 达成 Bloom 级
├─ 当前能力快照：各轴当前分（雷达实时更新）
├─ 缺学清单（累积）：需要学的 KP 列表 + 每个的缺口
├─ 建议下一步：今天该学哪 2-3 个 KP
└─ 若已有 ≥3 个连续不达标 KP → 提示走 S7 定制补充，别死磕
```

**20 题的分布约束**：T1-T5 各 4 题，但**具体考哪个 KP 由前面段的结果决定**（自适应出题）。所以 20 题不是固定题库，是 5 段自适应测试。

**缺学清单是 S3 的强制产出物**，格式：

```
| KP | 名称 | 当前 Bloom | 目标 Bloom | 缺口 | 归因 | 处置 |
|----|------|-----------|-----------|------|------|------|
| KP7 | 效果评估体系 | 2 | 5 | 60% | 上游 KP1/KP2 已达标 → 这层没学进去 | S5 补学 |
| KP12 | 多轮迭代策略 | 0 | 4 | 100% | 前置 KP7 未达标 → 先解前置 | 排队等待 |
| KP15 | 成本估算模型 | 1 | 4 | 75% | 已测且错 → 学歪了 | S7 定制补充 |
```

三种归因对应三条不同处置路径——这是分段测试比一次性测试强的地方：一次考完只知道"错了"，分段能区分"没学 / 学歪 / 被前置卡住"。

### 2.5.3 S4 杠杆前置调度（用户明确要求：重要/常用的 20% 挪前面）

#### 问题

用户原话：**"兴趣初期高后期低，难度递增"**。这意味着：

- 学习初期兴趣足，此时学的内容如果"不重要"，用户会迅速失去动力
- 越往后难度越高 + 兴趣越低，摩擦叠加，最容易崩盘

纯按"依赖图顺序 + 难度递增"排，会出现**最难的 KP 落在兴趣最低的时段**——这是最容易放弃的位置。

#### 解法：四条独立证据指向同一机制

| 证据                                              | 内容                                                          |
| ----------------------------------------------- | ----------------------------------------------------------- |
| **关键路径理论**（Kelley & Walker, 1959 CPM）           | 决定总完成时间的是依赖图上的**关键路径**，不是难度排序。延迟关键路径上的节点 = 延迟全部。            |
| **瓶颈节点实验**（灰束科技 Curriculum Crawler，12 概念数学 DAG） | 群智能自主发现"先学乘法而非减法"——因为乘法卡住 2 个下游概念，减法卡住 0 个。**学杠杆最高的先解锁一片**。 |
| **Pareto 核心 20%**（学习科学）                         | 承载 80% 结果的那 20% 概念；先练到高掌握，剩余 80% 明显变容易。                     |
| **Mastery learning**（Kulik 1990，108 项受控研究元分析）   | 每单元达标才进下一个，效果对弱学习者更强 → **放行条件必须硬**。                         |

#### 调度公式

```
leverage(KP) = 0.5 × hub_norm + 0.3 × value_norm + 0.2 × freq_norm

  hub   = deps 入度（它卡住几个下游 KP）→ 归一化 0-1
  value = 该 KP 支撑的目标动作权重（S0 依赖映射表算）→ 归一化 0-1
  freq  = 行业/日常使用频率（"最常用"的那 20%）→ 归一化 0-1
```

**排程三步**：

**Step 1 · 拓扑约束**（硬，不可违反）
  
deps 未达标的 KP，其后继不得出现在它前面。

**Step 2 · 杠杆前置**（软，在拓扑允许范围内重排）
  
在当前可学的 KP 集合里，选 `leverage` 最高的一批**前置**。

**Step 3 · 掌握度放行**（硬）
  
只有 `bloom_now ≥ target_bloom - 1` 才允许进下一个 KP。
  
（mastery learning 核心：不到标准不放行，不许"差不多会了"就往前赶）

#### Pareto 20% 的具体口径

不是拍脑袋的"最难的 20%"。两个信号交叉：

| 信号          | 怎么算                | 来源                               |
| ----------- | ------------------ | -------------------------------- |
| **最重要 20%** | 按 `value` 排序取前 20% | S0 的 G 动作依赖映射表 → 需要它才能完成目标动作的 KP |
| **最常用 20%** | 按 `freq` 排序取前 20%  | 检索时的行业实践频率 + 岗位 JD 出现频次          |

两个集合的并集 = **核心 20% 队列**，**永远排在学习路径最前面**（在拓扑允许范围内）。

> ⚠️ **冲突处理**：如果 Pareto 核心 KP 依赖尚未达标的 KP，**不许跳过前置**。这时做的是"先花最短路径打通前置"，而不是硬学核心。硬学的结果是"学过但没学会"，反而更挫败。

#### 每日队列怎么切

```
每日队列 = 拓扑可学集合中 leverage 最高的 3-5 个 KP
每 KP 预估 2-4 小时（按 Bloom 目标级与 KP 复杂度估）
切片原则：宁可一天 3 个学透，不要 5 个学半生
```

#### 这套调度对兴趣的意义

- **第 1 天就学最重要的 20%** → 早期投入产生真实进展，兴趣有正反馈来源
- **难度递增被"杠杆递减"部分抵消** → 前期啃的是核心（可能略难但价值高），后期是外围（价值低但难度不一定低）→ 感知难度曲线被压平
- **每个 KP 都有明确的"学会"标准** → mastery learning 的正反馈：达标感强于不确定感
    
  | **S8 档案** | 所有阶段 | 更新全局 profile：轴分、弱点池、雷达历史、证据链 | `profile.json` | 幂等：重跑不丢历史；弱点池只增不减（继承 材料驱动型 Skill 协议） |

## 4. S1 · 能力反推 → 能力轴定义

**轴 = 能力的横向切面**，不是知识点、不是 Bloom。

| 候选轴设计              | 判定 | 理由                                                               |
| ------------------ | -- | ---------------------------------------------------------------- |
| 轴 = 知识点（KP1..KP15） | ❌  | 轴数随主题变 → 跨主题不可比；且"记住 KP3 定义"不是能力。                                |
| 轴 = Bloom 六级       | ❌  | **纵向层级不是横向能力**。任何人在 L1 强 L6 弱是必然的 → 雷达图退化成单一量表，形状没有区分度。这是最容易犯的错。 |
| 轴 = 能力维度           | ✅  | 从目的反推，跨主题稳定，语义明确（"结构化拆解"在哪门学科都成立）。                               |

**全局轴池（建议初版 6 根，后续按需增补）**

| 轴 ID | 名称      | 判据（怎么算达标）            |
| ---- | ------- | -------------------- |
| A1   | 概念辨析    | 能说清两个近似概念的本质区别，而非背定义 |
| A2   | 结构化表达   | 能把复杂对象拆成有层级的、可判定的结构  |
| A3   | 边界与风险意识 | 能主动说出"这招在什么情况下不成立"   |
| A4   | 工程直觉    | 能判断一个方案落地时会卡在哪       |
| A5   | 判断取舍    | 面对多选项能给依据并承担结论       |
| A6   | 度量设计    | 能设计出可判真假的验证方式        |

**轴的生命周期**：全局轴池存在 `profile.json`，主题只**选轴子集**。
  
→ 同一根轴在"AI 产品经理"和"围棋"两个主题里都会被评分，**跨主题可比**。这是本引擎相对 材料驱动型 Skill 的核心增量。

## 5. S2 · 建知识图谱（防污染是重点）

用户原话是「去搜这个要达成这个目的需要拥有什么能力，需要搜什么资料」。问题在于：自由搜索会带回营销号、过期教程、互相矛盾的口径。

**来源分级**

| 级 | 类型                            | 处理                                     |
| - | ----------------------------- | -------------------------------------- |
| A | 官方文档 / 权威教材章节 / 论文 / 有署名的实战复盘 | 优先采信                                   |
| B | 高质量技术博客 / 行业深度分析 / 经典原始出处     | 可采信，需交叉验证                              |
| C | 营销号 / 无署名博客 / 内容农场            | ❌ 不进图谱                                 |
| D | 超过 2 年的时效性技术教程                | ❌ 不用（经典文献除外，如 Bloom 原文、Transformer 原文） |

**硬规则**

1. 每 KP 挂 ≥1 个来源链接，**挂不上来源 = 不进图谱**。
2. 两来源实质冲突 → 标 `conflict: true` + 并列两说，**不许 AI 自己编一个调和版本**。
3. 时效性内容必须带「截至 YYYY-MM」标注。
4. 图谱结构复用 材料驱动型 Skill 的**双标准筛选**：①推动该能力 ②当下行业还在用。不满足降级进「背景区」。
5. **每 KP 至少 1 条边**（deps / related / contrast），孤岛 KP = 图谱没建好，闸门打回。

**写完跑校验**：`python scripts/graph.py validate --graph <graph.json>` —— 检查孤岛、断边、环、缺来源。

**复用 材料驱动型 Skill**：材料驱动型 Skill 的 `补充与纠错.md` 模式（讲师没讲透的部分，AI 补齐并标来源）正是 S2/S7 需要的能力，直接沿用。

## 6. S3 · S4 · 分段诊断与杠杆排程

### S3 诊断：5 阶段 × 4 题（详细设计见 `references/graph.md` §5）

| 阶段 | 题数 | 探针                | 测     |
| -- | -- | ----------------- | ----- |
| T1 | 4  | 广度：每轴 1 题         | L2 理解 |
| T2 | 4  | 深度：T1 最弱 2 轴各 2 题 | L3 应用 |
| T3 | 4  | 迁移：跨轴组合题          | L3-L4 |
| T4 | 4  | 归因：对未达标 KP 追问     | L4-L5 |
| T5 | 4  | 验收：对目标动作出题        | L5-L6 |

**分段 vs 一次性**：分段能在每 4 题后立刻给「状态 + 下一步」，当天就能开始学；一次性只能全答完才知道缺什么，且中途疲劳会污染数据。

**归因三分法**（分段测试的独有价值）：没学过 / 被前置卡住 / 学歪了 → 对应 S5 排队 / 先解前置 / S7 定制补充。

**前置题 vs 后置题**

|          | 前置题（S3 诊断）     | 后置题（S5 学完） |
| -------- | -------------- | ---------- |
| 考什么      | **你会不会**       | **你能不能用**  |
| Bloom 目标 | 按 KP 目标级 −1 抽样 | 按 KP 目标级抽样 |
| 用途       | 定路径起点 + 归因     | 定是否过关      |

同一 KP 两套题库，不可混用。

### S4 排程：杠杆前置（四步）

```
Step 1 拓扑约束（硬）：deps 未达标的后继不得在前
Step 2 掌握度放行（硬）：bloom_now ≥ target_bloom − 1 才放行
Step 3 Pareto 前置（软）：核心 20% 尽量提前
Step 4 杠杆降序（软）：leverage 高的优先
```


```
leverage(KP) = 0.5 × hub_norm + 0.3 × value_norm + 0.2 × freq_norm
  hub   = deps 入度（它卡住几个下游 KP）
  value = 对目标动作的权重（S0 映射表算）
  freq  = 行业使用频率
```

**执行**：`python scripts/graph.py rank --graph <graph.json>` → 全图排序 + 今日可学队列 + 核心 20% 标记。

## 7. S6 · 雷达图：轴、算分、优劣判定

### 7.1 每根轴怎么算分

```
cov(A)   = 已测 KP 数 / 该轴 KP 总数
depth(A) = Σ bloom_now(KP) / (5 × 该轴 KP 总数)
score(A) = 100 × (0.3 × cov + 0.7 × depth)
```

- 必须混合两个因子：**只算深度**→ 学 3 个到 L5、剩 20 个没学，分虚高；**只算覆盖**→ 学 1 个到 L6，分虚高。
- bloom_now 口径：L1=1 … L6=6，未测=0（当作未测，不当 0 分处理；单独在覆盖率里体现）。

### 7.2 目标线（MBTI 没有的东西，也是这套东西的价值所在）

```
target(A) = 100 × (0.3 × 1.0 + 0.7 × 平均(target_bloom)/5)
```

雷达图上画**两条多边形**：当前（实线填充）+ 目标（虚线）。差距即训练空间。

### 7.3 优势/劣势判定（相对目标，不是相对别人）

| 判定        | 条件                            | 含义                     |
| --------- | ----------------------------- | ---------------------- |
| **真优势**   | gap ≤ 15 且 hub ≥ 2            | 接近目标 + 是枢纽 → 学它能解锁后面一片 |
| **伪优势**   | gap ≤ 15 但 hub = 0            | 学了不解锁任何东西 → 锦上添花，不是杠杆  |
| **关键短板**  | gap ≥ 30 且 hub ≥ 1            | 卡着别人的路 → 最高优先级补        |
| **可忽略短板** | gap ≥ 30 但 hub = 0 且不支撑任何目标动作 | 可以不补                   |
| **认知断层**  | gap ≥ 40 且其全部上游 KP 均已达标       | 不是没学，是学歪了 → 要重讲不是重练    |

### 7.4 每条判定必须回答 4 个问题

用户明确要求"为什么这个是优势，为什么那个是劣势，优劣势会带来什么影响，调整应该怎么调整"。逐条结构：

```
【关键短板】A6 度量设计 · gap 42 · hub 1
为什么是短板：证据链——KP7(评估三集) bloom_now=2，目标 L5，gap 60%；KP8(双线迭代) 未测。
为什么不是别的原因：上游 KP1/KP2 均已达标 → 不是前置没学，是这层没学进去。
带来什么影响：G3「设计评估集」依赖 A6 → 你的评估集设计能力直接卡在 L2，会导致【指标达标但体验变差】这类问题漏测
            （依据：S0 映射表 G3→A6）。
怎么调整：① 先补 KP7（3 天，目标 L4）② 用真实产品做一套基线/回归/边界三集 ③ 补 KP8 前置
```

## 7.5 · S5.5 结业测试（达成目的测试）· v4 新增

**触发**：用户主动提出「测试一下我能不能达成原来定的目的」。

### 三种测试的分工

| | S3 分段诊断 | S5 后置题 | **S5.5 结业测试** |
|---|---|---|---|
| 触发 | 引擎主动 | 每个 KP 学完 | **用户主动** |
| 考什么 | 你会不会 | 这个 KP 能不能用 | **能不能达成当初定的目的** |
| **判对错** | ✅ 逐题判级 | ✅ 逐题判级 | ❌ **全程不判对错，只记录** |
| 形式 | 客观题 | 2-3 道题 | **开放式问答，像真实场景/实操** |

### 为什么全程不判对错

1. **判对错会打断状态**——结业测试考「能不能做成事」，做事过程中被当场判错会进防御模式，反而测不出真实水平
2. **有些回答没有标准答案**——「你怎么给这个产品做评估」没有唯一解，判「错」是假的
3. **判级是后面的事**——先完整记录，最后统一复盘再指出问题，比逐题打断更准

### 六步流程

```
1. 出题（开放式，对着最终产出物）→ 2. 问答记录（只记不判）
→ 3. 答完全部，统一复盘（做得好的 / 问题 / 对照当初目的的结论）
→ 4. 更新雷达图 + 缺学清单（bloom_now 只升不降）
→ 5. 建议补充哪些知识
→ 6. 问用户要不要联网找（接 S7）
```

**结业测试记录必须进 Obsidian 归档**（学习历程的重要节点），但问答原文属学习数据，**不出现在任何公开内容**。

## 8. S7 · 补充知识：先问用户 → 联网取材 / 直接写讲义

用户原话："给用户把这个知识提炼出来，不是把知识给用户在网上找出来"。这是关键区分：

|    | S2 取材       | S7 补充                        |
| -- | ----------- | ---------------------------- |
| 方向 | 广度铺开（把料库建全） | 深度补漏（针对具体错答）                 |
| 手段 | 联网检索        | **AI 基于已有料库 + 弱点诊断生成**       |
| 产出 | KP + 来源     | 一份针对性讲解（含"你上次是这样答错的，所以问题在这"） |
| 落点 | 料库          | 料库 + 重排路径                    |

S7 硬性要求：

1. 必须**引用用户具体错答原文**作为开头锚点，否则退回"通用教程重贴"（这是 S7 最常见的失败模式）。
2. 内容来自料库 + 已核实公开事实，标出处。
3. 补完写回料库 → 触发 S4 重排 → 后续学习内容随之调整。

### 9.3 定时输出（每天主动推）

| ---- | -------------------------------------------------------------- |
