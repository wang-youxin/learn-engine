# learn-engine · 目的学习引擎

> 输入「我想学 X」，输出**能力画像 + 可执行学习路径 + 每日报告 + 能力雷达图**。
> 不是知识库，不是课程播放器，是一个**会跟你反复确认的学习状态机**。

## 它解决什么问题

大多数「AI 帮你学」的做法是：**给一份资料 → 出一份大纲 → 让你自己啃**。

三个问题它解决不了：

1. **不知道从哪开始** —— 大纲是给所有人写的，不是给你写的
2. **不知道自己会多少** —— 学完才发现前面有 3 个概念没懂，全白学
3. **不知道学这些有什么用** —— 分数涨了，但拿不出东西

这个引擎的做法是反过来的：**先定目的 → 反推需要什么能力 → 测你的底 → 按你的状态排顺序 → 学 → 测 → 出报告 → 补漏**。

## 核心特性

### 1. 目标驱动，不是材料驱动

你说「我想学 X」，它会先问清楚三件事才开始干活：

| 问什么 | 为什么必须问 |
|-------|-----------|
| **学什么 + 为什么学** | 目的是否成立，决定后面全歪不歪 |
| **你每天/每次能拿出多少时间** | 直接决定每日队列切几个知识点 |
| **学完要拿出什么** | 转行 → 简历 + 作品集；做内容 → 具体哪类内容 |

问完才开始找材料。**没拿到明确目的，不许进下一步。**

### 2. 知识图谱，不是知识树

知识点之间**连边**，三种边各有用途：

| 边 | 含义 | 用途 |
|---|------|------|
| `deps` | 硬前置：不懂 A 学不了 B | 排程硬约束 |
| `related` | 横向关联：常被混淆 / 特例 / 同源 | 教学时主动预警易混点 |
| `contrast` | 对立：同一维度的两个极端 | 同组出题测辨析能力 |

**每个知识点至少 1 条边**，孤立节点直接打回——没连边说明它没被真正理解。

### 3. 分段诊断：5 阶段 × 4 题 = 20 题

不是一次考 20 题。**每段 4 题，答完立刻判级、立刻给下一步**，当天就能开始学。

| 阶段 | 考什么 | 答完得到 |
|-----|--------|---------|
| T1 广度探针 | 每根能力轴 1 题 | 哪块完全没底 |
| T2 深度探针 | 往最弱的 2 根轴追问 | 这两轴卡在哪一层 |
| T3 迁移探针 | 跨轴组合题 | 是不是「碎片式会」 |
| T4 归因探针 | 对未达标的追问 | **没学过 / 学歪了 / 被前置卡住** |
| T5 产出物探针 | 直接对着最终产出物出题 | 离「拿得出手」还差什么 |

T4 的**归因三分法**是分段测试的独有价值——一次考完只知道「错了」，分段能区分三种错因，三种对应三条不同处置路径。

### 4. 能力雷达图：轴 = 能力维度

**不是知识点，不是 Bloom。**

- 轴 = 知识点 → 轴数随主题变，跨主题没法比
- 轴 = Bloom 六级 → **纵向层级不是横向能力**，任何人在 L1 强 L6 弱是必然，形状没有区分度
- ✅ 轴 = 能力维度 → 跨主题稳定可比，语义明确可判真假

而且**必须叠加目标线**（当前实线 + 目标虚线）：

```
score(A) = 100 × (0.3 × cov + 0.7 × depth)
```
- 只算深度 → 学 3 个到 L5、剩 20 个没学，分虚高
- 只算覆盖 → 学 1 个到 L6，分也虚高

**优劣判定相对你的目标，不相对别人**：

| 判定 | 条件 | 含义 |
|-----|------|------|
| 真优势 | gap ≤ 15 且 hub ≥ 2 | 接近目标 + 是枢纽，学它解锁后面一片 |
| 达标但非枢纽 | gap ≤ 15 且 hub = 0 | 到了目标，但不解锁任何东西——**看着是优势，其实不是杠杆** |
| 关键短板 | gap ≥ 30 且 hub ≥ 1 | 缺口大且卡着别人，最高优先级 |
| 认知断层 | gap ≥ 40 且上游全达标 | 不是没学，是学歪了 → 要重讲不是重练 |

### 5. 杠杆前置：先学最重要的 20%

**问题**：兴趣初期高后期低，而知识点难度递增。纯按依赖顺序排，最难的会落在兴趣最低的时段——最容易崩盘的位置。

**解法**（四条独立证据指向同一机制）：

| 依据 | 内容 |
|-----|------|
| 关键路径理论（CPM 1959） | 决定总完成时间的是依赖图上的关键路径，不是难度排序 |
| 瓶颈节点实验 | 12 概念数学 DAG 跑群智能，**AI 自主选择先学乘法而非减法**——乘法卡 2 个下游，减法卡 0 个 |
| Pareto 核心 20% | 承载 80% 结果的那 20%，先练到高掌握，剩下的明显变容易 |
| Mastery learning（Kulik 1990, 108 项元分析） | 每单元达标才进下一个，对弱学习者效果更强 → 放行条件必须硬 |

```
leverage(KP) = 0.5 × 枢纽度 + 0.3 × 目标权重 + 0.2 × 使用频率
```

排程四步：拓扑约束（硬）→ 掌握度放行（硬）→ Pareto 前置（软）→ 杠杆降序（软）

> 措辞说明：说「**先学**最重要的 20%」，不说「第 1 天就学」——前者是排在路径前段（可能前两三周），后者是字面的第一天，核心知识点依赖链长的话第一天根本学不完。

### 6. 结业测试：全程不判对错

用户主动提出「测试一下我能不能达成原来定的目的」时触发。

**为什么全程不判对错**：
1. 判错会打断状态——做事过程中被当场判错会进防御模式，测不出真实水平
2. 有些回答没有标准答案——「你怎么给这产品做评估」没有唯一解
3. 判级是后面的事——先完整记录，最后统一复盘再指出问题

流程：出题 → 问答记录（只记不判）→ **答完全部统一复盘** → 更新雷达图+缺学清单 → 建议补哪几块 → 问要不要联网找

### 7. ⚠️ 人机协同，不是自动流水线

**这是这个 Skill 最重要的设计决定。**

AI 每完成一个环节**必须停下来**把决策权交回用户，8 个卡点：

| 卡点 | 时机 | 问什么 |
|-----|------|-------|
| K1 | S0 前 | 学什么 + 为什么学 + **用多少时间** + **拿什么产出** |
| K2 | S2 后 | 材料来源摊给你看，A/B 级各几个、剔除了什么、有没有冲突 |
| K3 | S2→S3 | 现在测一下？5 段共 20 题 |
| K4 | S3 后 | 初版顺序排好了，**要不要把某块重点前移**？时间够不够 |
| K5 | 每个知识点学完 | **要不要现在测**？不测记成「学过但未验证」 |
| K6 | 归档前 | **要不要存档**？存哪 |
| K7 | 补充前 | 补哪几块？**素材从哪来——我去网上找还是你直接写** |
| K8 | 结业测试 | 要不要做一次结业测试？ |

**为什么必须这样**——根因是**决策幻觉**：

> AI 一旦自主决策久了，会产生幻觉：**开始觉得自己做的一切决策都是对的、都是用户想做的**。而实际上那些决策从头到尾没有一个人确认过。
>
> 表现：排序说是「为你好」，选材说是「最优解」，跳过测试说是「效率更高」。
> 后果：用户拿到一份看起来很专业、但完全不符合他真实意图的方案，且**没有任何环节能让他发现哪里错了**。
> 唯一解药：**在每个决策点让用户实际回一次话**。用户没参与过的决策，不是用户的决策。

推论：AI 的默认值只能是「待用户确认的建议」，不能是「已执行的决定」。

用户覆盖 AI 建议时：**执行用户的 → 在产物里标注「用户覆盖了 AI 重排建议」→ 下次重排优先再问一次**。

### 8. 产出物优先于分数

用户要的是「拿得出手的东西」，不是「分数涨了」。

```
目标动作：G1 写 PRD / G2 归类判断 / G3 设计评估集
   ↓ 反推
最终产出物：一份可投简历 + 1-2 个作品集案例 + 3-5 个面试能讲的判断
验收标准：简历投出去 ≥10 家收到 ≥2 个面试邀约
         每个案例能扛住「这决策为什么这么做」的追问
```

落地三处：S0 必产出物+验收标准 ｜ T5 直接考产出物 ｜ **报告首段是「离你的产出物还有多远」**。

**写不出验收标准的动作 = 目标没定清。**

```
├── references/
│   ├── interaction.md              # 引导规范：卡点话术、决策幻觉根因、失败模式
│   ├── graph.md                    # 知识图谱：KP 单位、三种边、杠杆排序、分段测试
│   ├── radar.md                    # 雷达图算分、优劣判定、影响推演模板
│   ├── axes.md                     # 能力轴定义、判据、扩轴规则
│   ├── sources.md                  # 来源分级、检索策略、拆 KP 规范
│   └── archive.md                  # 档案 schema、幂等规则、迁移协议
├── scripts/
│   ├── graph.py                    # 图谱校验 + 杠杆排序 + 拓扑分层
│   ├── radar.py                    # 雷达图生成 + 轴分计算 + 优劣判定
│   └── sync_obsidian.py            # 同步到 Obsidian Vault
├── example/graph.json              # 示例图谱，可直接跑通三个脚本
└── 设计/学习引擎结构设计.md          # 完整设计文档
```

**零第三方依赖**，三个脚本纯标准库。

## 安装

### 方式一：直接放（推荐）

```bash
git clone https://github.com/<your-user>/learn-engine.git
cp -r learn-engine ~/.workbuddy/skills/learn-engine/
```

Windows：
```powershell
git clone https://github.com/<your-user>/learn-engine.git
Copy-Item -Recurse learn-engine "$env:USERPROFILE\.workbuddy\skills\learn-engine"
```

### 方式二：让 Agent 装

```
"帮我从 GitHub 安装这个 skill：<repo-url>"
```

### 装完重建 gateway 索引

如果你用 [gateway](https://github.com/wang-youxin/gateway) 做 Skill 导航，装完必须重建索引（否则新 Skill 不会被检索到）：

```bash
node ~/.workbuddy/skills/gateway/refresh-index.js
```

> ⚠️ 新装 Skill 后如果 gateway 检索不到，多半是索引没重建，或 `refresh-index.js` 的 `CATEGORY_RULES` / `GROUP_RULES` 里没给它归类（这两个规则是白名单式匹配，名字不在名单里会掉进 `other` 桶）。

## 使用

```
"我想学 AI 产品经理"
"帮我规划怎么学 RAG"
"我学得怎么样了"
"今天学完了，生成报告"
"做一次结业测试，看我能不能达到目的"
```

首次使用会依次经过 K1 → K8 的引导问答。

### 目录约定

Skill 会在**当前工作目录**下创建：

```
<工作目录>/学习档案/
├── profile.json              # 全局：能力轴定义 + 各轴得分 + 弱点池 + 雷达历史
└── T-<主题slug>/
    ├── 立项.json / 立项.md
    ├── 知识图谱.md / graph.json
    ├── 路径.md                # 排序结果 + 每日队列
    ├── 诊断.md
    ├── 状态.json
    ├── 结业测试/YYYYMMDD.md
    ├── 补充/
    └── 报告/YYYYMMDD.md + 雷达图.html
```

### 脚本用法

仓库里带了一个示例图谱，可以直接跑通：

```bash
# 校验图谱（孤岛 KP / 断边 / 环 / 缺来源）—— 不过不进诊断阶段
python scripts/graph.py validate --graph example/graph.json

# 杠杆排序 + Pareto 核心 20% + 今日可学队列
python scripts/graph.py rank --graph example/graph.json

# 拓扑分层（看依赖关系）
python scripts/graph.py topo --graph example/graph.json

# 雷达图（当前实线 + 目标虚线）
python scripts/radar.py --profile 学习档案/profile.json \
                        --topic   学习档案/T-<slug> \
                        --out     学习档案/T-<slug>/报告/雷达图.html

# 同步到 Obsidian（daily 追加 + wiki 双链笔记 + index.md 更新）
python scripts/sync_obsidian.py --topic-dir 学习档案/T-<slug> \
                                --vault "你的 Obsidian Vault 路径" \
                                --date 2026-10-23
```

`radar.py --demo` 和 `graph.py demo` 可以不建任何数据直接看效果。

## Obsidian 归档

引擎会把学习记录同步进你的 Obsidian Vault，遵守五层结构：

| 产物 | Vault 位置 | 层 |
|-----|-----------|-----|
| 每日学习记录 | `daily/YYYY-MM-DD.md` | D 产出层 |
| 知识点笔记（含 `[[双链]]`） | `wiki/通用/<主题>.md` + 每知识点一篇 | B 提炼层 |
| 学习方法论（用过 3 次） | `skills/` | C 技能层 |

同步脚本会确保：YAML frontmatter 齐全、正文有 `[[wikilink]]`、`index.md` 已更新。**不会删除 Vault 内任何文件。**

> 跨 vault 引用注意：不同 vault 之间的 `[[双链]]` 是死链，跨库引用请用普通文本 + 注明出处。

## 设计上的几个硬约束

| 约束 | 说明 |
|-----|------|
| **证据优先** | 每个知识点必须挂来源；每个分数必须能追到一次测试 |
| **状态驱动路径** | 顺序由学习者当前状态算出，状态变顺序变 |
| **影响力先于分数** | 轴的优先级看它卡住谁，不看它自己分多低 |
| **人机协同** | 每个决策点让用户实际回一次话（防决策幻觉） |
| **产出物优先** | 用户要拿得出手的东西，不是分数 |

### 质量闸门

1. **来源真实性** — 抽 KP 核链接真实且内容支持
2. **图谱完整性** — 无孤岛 / 断边 / 环 / 缺来源
3. **分数有据** — 每个判定能引用 KP ID + 测试记录
4. **影响有源** — 影响推演能追到目标动作，追不到就删
5. **补充有锚** — 补充材料开头引用用户错答原文
6. **冲突未调和** — 来源冲突保留并列，不许编折中版本
7. **Obsidian 合规** — frontmatter / 双链 / index.md
8. **⚠️ 引导完整性** — 回查对话，K1/K3/K4/K5/K6 用户是否都实际回过话

## 常见问题

**Q：为什么不用 Bloom 六级当雷达轴？**
Bloom 是纵向层级不是横向能力。任何人在 L1 强 L6 弱是必然结果 → 雷达图退化成一个量表，形状没有区分度。轴必须是能力的横向切面。

**Q：为什么测试要分段？**
一次 20 题有三个问题：用户中途疲劳污染数据、结果太晚当天学不了、全答完才知道缺什么无法中途调整。分段后每 4 题就能给「状态 + 下一步」。

**Q：杠杆排序会不会牺牲体系完整性？**
会一点，但这是有意的取舍。兴趣衰减是真实约束，如果把最难的放在兴趣最低期，放弃率会显著上升。依赖约束是硬的（不牺牲），Pareto 前置是软的（可被用户推翻）。

**Q：跳过测试会怎样？**
记 `bloom_now = 0` + 状态 `learned_unverified`。雷达图上显示为浅色，报告会注明。**不会被算成已掌握。**
